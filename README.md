# 小云 Studio

**一个网页导播台，把 AI 主播、演示稿、弹幕、音频混音和 RTMP 推流放到同一套独立服务里。**

部署到 Linux 后，由服务器上的无界面 Chromium 渲染画面，FFmpeg 编码、录制并推流。电脑上的网页用于控制和监听；关闭控制网页不影响已启动的后台推流。运行时不依赖 DSH、Cordis、OBS 或桌面窗口采集。

## 已有能力

| 能力 | 使用方式 |
| --- | --- |
| 一体化导播 | 预览合成画面，切换标准、人物、演示稿和绿幕布局；配置标题、字幕、人物与社群二维码 |
| 直播场景 | 新建、复制、改名和切换；复用提示词、演示稿、固定口播、声音和平台配置 |
| 直播场次 | 每次实际推流或录制成功后独立建档；保存时长、分平台人数、完整弹幕和播出事件，可导出 |
| 多平台推流与录像 | ＋ 添加平台，分别设置 RTMP/RTMPS 地址和密钥；同一画面同时输出，单路启停/重试，录制独立 |
| AI 主讲与人机互聊 | 知识分享 / 带货主播人格预设、自定义提示词、开场、结束语、当前页讲解、多轮展开；文字提问；可选麦克风、闭麦和语音打断 |
| HTML / PDF 演示 | 上传或打开网页演示稿；提取当前页文字，AI 决定何时翻页；讲完可循环，保留抽奖历史 |
| 口播与声音 | 预录音一键播报；腾讯云或兼容接口合成；播放时准备后续文本/语音；完整口播之间穿插弹幕 |
| BGM 与监听 | 四首附来源的 CC0 音乐；音量、说话时压低伴奏；网页耳机监听后台混音 |
| 四平台弹幕 | 哔哩哔哩、抖音、快手、视频号独立后台登录与采集，弹幕保留来源；可接外部弹幕桥 |
| 节目编排 | 环节可启停和调序，支持多互动、纯讲解、不抽奖、不用结尾；独立互动频率与引导文案 |
| 秒杀与抽奖 | 定时秒杀二维码；抽奖可多选弹幕、人气、间隔或固定时刻规则，任一满足时触发且合并同时触发 |
| 长播与多端控制 | 一个服务维护统一状态；有界上下文、最近两分钟最多 100 条弹幕、两分钟无声恢复；多台电脑同步操作 |
| 数据导出 | 导出 JSON / CSV / Markdown 报告，保留采样时间与字段来源，区分观看人数、观看次数等指标 |

## 用 Docker 启动

需要一台安装了 Docker Compose 的 Linux 主机。

```sh
git clone https://github.com/sliverp/xiaoyun-studio.git
cd xiaoyun-studio
cp .env.example .env
# 编辑 .env：STUDIO_ADMIN_PASSWORD 填至少 12 个字符的独立管理员密码
# 保留其他设置即可先体验预录口播与录像

docker compose up -d --build
```

访问 `http://服务器地址:18080`，使用设置的密码登录。首次使用：

1. 登录后进入「直播场景」，打开「原配置」体验内置演示，或选择「新建场景」「复制当前场景」。创建后仍在列表中，点击「打开场景」进入导播台；顶部显示当前场景名称。
2. 在「画面展示」设置演示稿、讲解笔记、布局与包装，在「主播设定」设置人物身份、显示名称和声音。
3. 在「节目编排」设置开场、收尾、固定口播、抽奖、秒杀与背景音乐；在「外部连接 → AI 与语音服务」配置模型和语音服务，统一点击「保存场景设置」。**内置演示模式只播放明确标注的固定录音**，不会把任意文案伪装成合成结果。
4. 在「外部连接 → 直播平台」点「＋ 添加平台」，分别填写推流地址、密钥和直播间，点击「保存连接」，再按需连接弹幕或扫码登录。仅录像时，在「输出与录制」中勾选「同时保存本地录制文件」，可以不添加推流目的地。
5. 回到「直播控制」，可在「节目快捷操作」点「播报」试听已有录音；空白场景需先添加口播。正式输出时点「开始推流 / 录制」，自动讲解另点「开始 AI 播报」；两者独立控制，无需另外开启 OBS。
6. 首次点击口播、提问或开始 AI 播报时，网页会先接通本机声音；也可以在混音台手动开关。「本机声音 · 静音」只影响当前浏览器，服务器的推流和录制仍有声音；手动静音后需再次点击该按钮恢复。在另一台设备打开同一地址即可看到统一场景和运行状态，监听开关由各浏览器单独控制。

7. 「直播场次」查看每次实际开播的时长、分平台人数、弹幕和事件；推流或录制成功后自动建档。使用外部软件时，手动「记录外部开播」，下播后结束本场。返回场景列表会关闭本机声音和麦克风，后台输出继续。

![按流程、口播、活动与音乐组织节目](docs/assets/workspace-program.png)

固定口播编辑、模型与声音设置、保存方式详见 [配置与声音](docs/configuration.md)。

公网使用应配置 HTTPS 和访问控制。麦克风需要 HTTPS 或 localhost 安全环境。配置、登录凭据、上传素材、录音和报告都保存在持久卷；`docker compose down` 不删除它们。`down -v` 会删除数据，勿用于升级。详见 [部署与操作](docs/deployment.md)。

## 本地开发

需要 Node.js 24、Chrome/Chromium；`npm ci` 会安装所需依赖和 FFmpeg 静态工具。Linux 镜像使用系统 FFmpeg。

```sh
npm ci
npm start
```

默认仅监听 `127.0.0.1:18080`。首次启动且未提供管理员密码时，程序随机生成密码并将位置提示为 `.data/first-login.txt`，不会在日志中打印密码；已有凭据时继续使用。`npm start` 在前台运行，长期后台托管和自定义端口见 [部署与操作](docs/deployment.md#本机-nodejs-与后台托管)。可通过 `CHROMIUM_PATH` / `FFMPEG_PATH` 指定工具位置。

```sh
npm run check
npm test
npm run test:media
```

## 导入旧项目素材

导入是复制操作，不修改旧目录、不连接旧服务。密钥、浏览器会话、观众记录和旧服务运行状态不会被复制。

执行前停止新 Studio 的服务进程，导入后重新启动；自定义数据目录需显式传 `--data`，操作范围见 [迁移说明](docs/migration.md)。

```sh
npm run migrate -- --source /path/to/previous-project
# 确认导入结果后，可显式加 --apply 将新服务切换为导入的演示稿、话术与录音
```

# 部署与操作

一个服务可以保存多个直播场次，同时只运行一个当前场次。多个浏览器控制同一个场次和导播状态；场次切换会先停止当前运行，不能用于同时运行多场直播。需要独立并行的直播间时，为每个直播间部署独立实例和数据卷。场次操作见 [按直播场次保存](projects.md)。

## Linux 服务

根目录 Dockerfile 安装 Node.js 24、Chromium、FFmpeg 和中日韩字体。Compose 的 studio 服务以普通用户运行，默认外部端口 18080，持久数据在 studio_data 卷，Chromium 共享内存为 512MB。后台渲染不依赖图形桌面、OBS 或用户浏览器的打开状态。

配置 `.env` 中的管理员密码后运行 `docker compose up -d --build`。服务重启会结束当前编码进程，**不会自动恢复 AI 播报或对外推流**。管理员确认后重新开始。奖品和已触发活动历史保留，旧的未完成抽奖窗口会取消。升级前应停止播报和输出，再按本文末尾的步骤备份。

```sh
docker compose ps
docker compose logs --tail 100 studio
curl --fail http://127.0.0.1:18080/health
```

端口以 `.env` 的 `STUDIO_PORT` 为准。`/health` 只确认 HTTP 服务响应；Chromium、FFmpeg、模型、声音和平台接收情况仍需分别检查。

初次使用可保持演示模式，用预录音检查画面、音量和录像。随后设置：

| 设置 | 内容 |
| --- | --- |
| 主模型 | 兼容 Chat Completions 的 API 根地址、模型名、独立 API Key；最多三条备份 |
| 腾讯云语音 | SecretId、SecretKey、VoiceType 和语速；默认音色字段为 602003，是否开通及额度以账号为准 |
| 兼容语音 | 兼容 `/audio/speech` 的 API 根地址、模型、音色和密钥 |
| 演示稿 | 公网 HTML 地址，或上传 HTML / PDF；PPTX 请先转成 PDF 或兼容 HTML |
| 推流 | 平台提供的 RTMP/RTMPS 服务器地址和单独密钥；密钥不要写进服务器地址 |

模型主通道有备份时约 10 秒超时后切换；其他通道请求上限约 30 秒。失败通道有冷却。该机制不能保证任何模型提供方始终可用。

## 本机 Node.js 与后台托管

安装 Node.js 24、Chrome/Chromium 并执行 `npm ci`，在仓库目录运行 `npm start`。默认仅监听 `127.0.0.1:18080`；这是前台进程，退出终端会结束服务。长期运行可交给 macOS launchd、Linux systemd 或容器管理器，仓库不自动安装宿主机后台服务。

| 环境变量 | 用途 |
| --- | --- |
| `PORT` / `STUDIO_HOST` | Node 进程监听端口与地址，默认 `18080` / `127.0.0.1`；Compose 对外端口用 `STUDIO_PORT` |
| `STUDIO_DATA_DIR` | 持久数据根目录，默认仓库 `.data`；Docker 镜像固定为 `/data` |
| `CHROMIUM_PATH` / `FFMPEG_PATH` | 自动检测不到时，指定可执行文件绝对路径 |
| `STUDIO_ADMIN_PASSWORD` | 至少 12 个字符；每次启动提供此值都会更新管理员密码 |
| `STUDIO_SECURE_COOKIE` | HTTPS 反向代理后设为 `1`；直接 HTTP 本机访问保持 `0` |

例如使用本机端口 18088：

```sh
PORT=18088 STUDIO_HOST=127.0.0.1 npm start
```

没有设置管理员密码且数据目录中还没有登录凭据时，首次密码写入数据根目录的 `first-login.txt`，不会在日志中输出密码。已有凭据时不会重新生成。重启会清除浏览器登录会话，需要使用当前密码重新登录；关网页或退出登录不会停止已运行的后台直播。

后台托管应固定工作目录、Node 可执行文件和数据目录，停止时发送 SIGTERM 并留出清理时间；Compose 已设置 20 秒退出宽限。不要让两个 Studio 进程同时使用同一数据目录。首次迁移场次会复制原有录像和浏览器资料，应预留磁盘空间，避免进程管理器在迁移尚未完成时反复重启。

## 麦克风互聊

文本提问直接可用。语音输入还需要识别服务，可使用可选的 CPU SenseVoice 容器：

```sh
# 首次部署前可在 .env 填写 STUDIO_ASR_BASE_URL=http://asr:10095/v1
# 首次启动会下载识别模型，需访问模型下载站点

docker compose --profile voice up -d --build
```

只在内部网络暴露识别端口。浏览器允许麦克风后选择输入设备；闭麦只关闭本机麦克风输入，不停止 AI。识别持续监听，较长且超过噪声阈值的语音可打断当前输出。请戴耳机或使用具有回声消除的设备，避免扬声器回灌被识别为新提问。识别精度和噪声适应需要用实际设备调整。

`STUDIO_ASR_BASE_URL` 仅在首次创建「原配置」时写入。已经初始化的服务，或之后新建的空白场次，需要在该场次「AI 与语音」中填写识别地址并保存；单独修改 `.env` 不会更新已保存场次。浏览器录音传到 Studio，再由 Studio 请求识别服务，因此 `http://asr:10095/v1` 是容器内部地址。

## 画面与演示稿

人物、演示稿、字幕、社群二维码、秒杀二维码都在后台合成页中渲染。标准布局接近一张完整直播框架：主内容在左侧，人物与社群入口在右侧，秒杀作为独立悬浮层。表情硬切；角色嘴型使用实际播报音量驱动。绿幕布局仍可用于其他工作流。

HTML 应包含可读正文和可识别的当前页，并提供翻页函数；详见演示稿协议。PDF 逐页渲染并提取文本。扫描图片 PDF 和只有图片的网页不会自动获得可靠文字；请提供补充讲解笔记。当前模型讲解依据提取的文字与笔记，不能声称已经识别了所有图片细节。

单个 HTML 文件上传可包含内联样式和脚本；有外部资源的演示稿应使用可访问的完整网站。动画和复杂页面可能降低合成帧率。默认 1280×720、15fps；开始正式活动前应在目标服务器逐步调参并验证实际编码速率。

## 讲解控制和输出控制

- 「暂停」保留当前口播位置；恢复后从暂停处接着播放。推流仍在进行。
- 「重新开始」将讲解和演示稿回到开头，保留已使用奖品与活动触发历史。
- 「结束并告别」等待整段完成，播放结束语后停止 AI；不会立即中断句子。
- 「立即停止」中断当前声音，结束 AI 讲解。后台输出按钮独立管理推流和录像。
- 「停止推流 / 录制」关闭编码并结束当前推流和录像文件。结束对外直播时必须确认输出已停止。

自动循环启用时，讲完最后一页回到第一页继续讲解；主动结束仍是结束。控制端关闭、刷新、切换设备不会停止服务器已经运行的输出。点击固定口播、提问或开始 AI 播报时，网页在用户点击中接通本机声音，等待音频连接就绪后再提交播放。手动选择本机静音后会保留该偏好；需要收听时在混音台恢复。监听与推流时钟分离，不需要先推流才能试听。固定口播的配置步骤及无声排查见 [配置与声音](configuration.md)。

## 弹幕和活动

在「平台与推流」点「＋ 添加平台」，选择视频号或其他平台，保存连接后在平台卡片点「连接弹幕」。服务启动该连接自己的无界面浏览器；需要认证时点「扫码登录」，在导播台查看真实页面并用手机完成登录。实际直播仍需要平台侧的开播权限及操作。未收到真实消息时明确显示等待状态；浏览器已连接不代表已收到弹幕，也不代表已经对外开播。详细步骤与各平台边界见 [多平台接入](platforms.md)。也可以使用受保护的弹幕接入口。

弹幕只取最近两分钟、最多 100 条未处理内容。AI 可以概括共同问题或点名回复；不会保证每条弹幕都被朗读。完整口播之间调度弹幕与互动，语音合成内部切块不意味着中途插入弹幕。

秒杀按北京时间间隔和开始/结束窗口排队，当前整段播完再提醒。上传二维码后设置 1–30 分钟的显示时长；二维码独立于当前页，显示期间仍可翻页，到期自动收起。口令抽奖另有奖池和触发规则，首个符合参与窗口和口令的用户中奖，中奖与奖品历史持久保存。请按实际平台活动规则使用。

## 网络、监控和容量

公网建议使用 HTTPS 反向代理，参考 [Caddy 示例](../deploy/Caddyfile.example)。只有经过认证的管理员可查看节目预览、素材、平台登录截图和直播数据。`STUDIO_SECURE_COOKIE=1` 应配合 HTTPS 启用。控制台本身不应匿名暴露。

推流需要访问平台目的端口；拉取演示稿、API 和视频号后台需要相应出网能力。默认阻止演示稿访问内网和元数据；确有内网演示需求时，部署者可显式设置 `ALLOW_PRIVATE_PRESENTATIONS=1`，云元数据仍阻止。容器不应挂载宿主机凭据或 Docker socket。

从 4 vCPU、8GB 内存的测试主机开始评估是容量规划建议，不是已测承诺。画面复杂度、分辨率、帧率、CPU 型号和识别模型都会影响资源。录制空间按码率持续增长，例如 2500kbps 视频加 128kbps 音频约每小时 1.2GB；以实际文件为准。需要自行安排录像/历史日志归档和磁盘告警；本版本不会自动删录像。请先做长时间彩排，再进行正式长播。

## 备份、升级与恢复

备份整个数据根目录：包含服务登录信息、场次清单、共享上传素材，以及所有场次的设置、密钥、登录目录、奖品历史、录音和录像。只复制当前场的 `settings.json` 不能恢复完整服务。备份含账号与观众资料，应与原数据保持相同访问权限；在切换场次或重启前，先导出需要保留的当前报告。

Compose 部署可在仓库目录执行下例。先保存设置、在页面停止 AI 和全部输出，再停止服务，使配置、浏览器会话和录像不再写入。归档路径位于宿主机的 `backups/`，不在数据卷中：

```sh
set -eu
umask 077
mkdir -p backups
studio_archive="backups/studio-data-$(date +%Y%m%d-%H%M%S).tar.gz"
docker compose stop studio
docker compose run --rm --no-deps -T --user root studio tar -C /data -czf - . > "$studio_archive"
tar -tzf "$studio_archive" > /dev/null
docker compose start studio
```

另行妥善保存部署使用的 `.env` 和代码版本。升级时在完成备份后拉取代码，再执行 `docker compose up -d --build`；不要使用 `docker compose down -v`，它会删除持久卷。

恢复时使用与归档匹配的代码版本，在新的部署目录准备 `.env` 和空数据卷，先构建镜像。以下命令仅向空卷恢复，目标非空时拒绝解包；不会为你清空现有数据：

```sh
set -eu
studio_archive="backups/studio-data-YYYYMMDD-HHMMSS.tar.gz"
tar -tzf "$studio_archive" > /dev/null
docker compose build studio
docker compose run --rm --no-deps -T --user root studio sh -c \
  'test -z "$(ls -A /data)" || { echo "目标数据卷非空，请使用新的空卷" >&2; exit 1; }; tar -C /data -xzf -' < "$studio_archive"
docker compose up -d studio
```

本机 Node 部署遵循相同顺序：停止持有数据目录的后台服务，完整复制 `STUDIO_DATA_DIR`，再启动。恢复后核对场次列表、口播、素材、奖品记录和平台登录；检查录像可播放，手动确认后才开始 AI 或推流。新数据结构不保证被旧版程序读取，回退时应连同升级前的完整数据备份恢复，避免用旧程序直接打开已升级的卷。

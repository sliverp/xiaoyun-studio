# 部署与操作

这是单管理员、单直播实例服务。多个浏览器控制同一个导播状态，不是相互隔离的多租户平台。需要多直播间时，应为每个直播间部署独立实例和数据卷。

## Linux 服务

根目录 Dockerfile 安装 Node.js 24、Chromium、FFmpeg 和中日韩字体。Compose 的 studio 服务以普通用户运行，默认外部端口 18080，持久数据在 studio_data 卷，Chromium 共享内存为 512MB。后台渲染不依赖图形桌面、OBS 或用户浏览器的打开状态。

配置 `.env` 中的管理员密码后运行 `docker compose up -d --build`。升级时备份数据卷，拉取新版本，重新构建并启动；服务重启会结束当前编码进程，**不会自动恢复对外推流**。管理员确认后重新开始输出。奖品和已触发活动历史保留，旧的未完成抽奖窗口会取消。

初次使用可保持演示模式，用预录音检查画面、音量和录像。随后设置：

| 设置 | 内容 |
| --- | --- |
| 主模型 | 兼容 Chat Completions 的 API 根地址、模型名、独立 API Key；最多三条备份 |
| 腾讯云语音 | SecretId、SecretKey、VoiceType 和语速；默认音色字段为 602003，是否开通及额度以账号为准 |
| 兼容语音 | 兼容 `/audio/speech` 的 API 根地址、模型、音色和密钥 |
| 演示稿 | 公网 HTML 地址，或上传 HTML / PDF；PPTX 请先转成 PDF 或兼容 HTML |
| 推流 | 平台提供的 RTMP/RTMPS 服务器地址和单独密钥；密钥不要写进服务器地址 |

模型主通道有备份时约 10 秒超时后切换；其他通道请求上限约 30 秒。失败通道有冷却。该机制不能保证任何模型提供方始终可用。

## 麦克风互聊

文本提问直接可用。语音输入还需要识别服务，可使用可选的 CPU SenseVoice 容器：

```sh
# 在 .env 中填写 STUDIO_ASR_BASE_URL=http://asr:10095/v1
# 首次启动会下载识别模型，需访问模型下载站点

docker compose --profile voice up -d --build
```

只在内部网络暴露识别端口。浏览器允许麦克风后选择输入设备；闭麦只关闭观众侧输入，不停止 AI。识别持续监听，较长且超过噪声阈值的语音可打断当前输出。请戴耳机或使用具有回声消除的设备，避免扬声器回灌被识别为新提问。识别精度和噪声适应需要用实际设备调整。

## 画面与演示稿

人物、演示稿、字幕、社群二维码、秒杀二维码都在后台合成页中渲染。标准布局接近一张完整直播框架：主内容在左侧，人物与社群入口在右侧，秒杀作为独立悬浮层。表情硬切；角色嘴型使用实际播报音量驱动。绿幕布局仍可用于其他工作流。

HTML 应包含可读正文和可识别的当前页，并提供翻页函数；详见演示稿协议。PDF 逐页渲染并提取文本。扫描图片 PDF 和只有图片的网页不会自动获得可靠文字；请提供补充讲解笔记。当前模型讲解依据提取的文字与笔记，不能声称已经识别了所有图片细节。

单个 HTML 文件上传可包含内联样式和脚本；有外部资源的演示稿应使用可访问的完整网站。动画和复杂页面可能降低合成帧率。默认 1280×720、15fps；开始正式活动前应在目标服务器逐步调参并验证实际编码速率。

## 讲解控制和输出控制

- 「暂停」保留当前口播位置；「继续」从暂停处接着播放。推流仍在进行。
- 「重新开始」将讲解和演示稿回到开头，保留已使用奖品与活动触发历史。
- 「结束并告别」等待整段完成，播放结束语后停止 AI；不会立即中断句子。
- 「立即停止 AI」中断当前声音，结束讲解。后台输出按钮独立管理推流和录像。
- 「停止输出」关闭编码和当前推流/录像文件。结束对外直播时必须确认输出已停止。

自动循环启用时，讲完最后一页回到第一页继续讲解；主动结束仍是结束。控制端关闭、刷新、切换设备不会停止服务器已经运行的输出。浏览器耳机监听需要用户主动开启，以满足音频播放权限；监听网页与推流时钟分离。

## 弹幕和活动

点「连接视频号」，服务启动独立的无界面后台浏览器，在导播台中显示微信登录二维码。扫码后页面保持运行。实际直播需要在视频号平台完成开播，本服务不会代替平台的直播创建、开播和账号权限。未收到真实消息时明确显示等待状态；“后台已连接”不代表“已收到弹幕”。这部分依赖平台非公开后台响应，平台变更后可能需要适配。也可以使用受保护的弹幕接入口。

弹幕只取最近两分钟、最多 100 条未处理内容。AI 可以概括共同问题或点名回复；不会保证每条弹幕都被朗读。完整口播之间调度弹幕与互动，语音合成内部切块不意味着中途插入弹幕。

秒杀按北京时间间隔和开始/结束窗口排队，当前整段播完再提醒。上传二维码后设置 1–30 分钟的显示时长；二维码独立于当前页，显示期间仍可翻页，到期自动收起。口令抽奖另有奖池和触发规则，首个符合参与窗口和口令的用户中奖，中奖与奖品历史持久保存。请按实际平台活动规则使用。

## 网络、监控和容量

公网建议使用 HTTPS 反向代理，参考 deploy/Caddyfile.example。只有经过认证的管理员可查看节目预览、素材、平台登录截图和直播数据。`STUDIO_SECURE_COOKIE=1` 应配合 HTTPS 启用。控制台本身不应匿名暴露。

推流需要访问平台目的端口；拉取演示稿、API 和视频号后台需要相应出网能力。默认阻止演示稿访问内网和元数据；确有内网演示需求时，部署者可显式设置 `ALLOW_PRIVATE_PRESENTATIONS=1`，云元数据仍阻止。容器不应挂载宿主机凭据或 Docker socket。

从 4 vCPU、8GB 内存的测试主机开始评估是容量规划建议，不是已测承诺。画面复杂度、分辨率、帧率、CPU 型号和识别模型都会影响资源。录制空间按码率持续增长，例如 2500kbps 视频加 128kbps 音频约每小时 1.2GB；以实际文件为准。需要自行安排录像/历史日志归档和磁盘告警；本版本不会自动删录像。请先做长时间彩排，再进行正式长播。

# 各环节实际提示词与连续对话

控制台「主播设定 → 查看各环节实际提示词」展示当前场景已保存的完整文本，包含自定义人格。本文件记录通用规则与默认环节任务；实际文案由 `server/director-prompts.mjs` 同时提供给模型和查看接口。

## 由代码决定每个环节收到什么

系统消息始终包含「场景人格和公开身份 + 公共规则 + 当前环节任务」。用户消息只放动态数据，由 `server/director-context.mjs` 的环节白名单组装，不把整份弹幕历史注入所有环节。

| 环节 | 动态上下文 |
| --- | --- |
| 内容讲解 | 当前页事实和笔记、代码提供的页内段号/本段重点/最低段数/翻页许可、最近三段实际讲解、当前真实播放、前序未播计划、尚待落实的讲解要求、表达偏好 |
| 弹幕回应 | 最近最多100条弹幕的完整窗口及每条处理状态、当前页要点、最近实际讲解和三分钟内的互动问题；只有问到时才附在线人数、活动或抽奖数据 |
| 互动引导 | 最近讲解、当前页摘要、近期互动问题、表达偏好；不携带旧弹幕答复、活动模板或未来页计划 |
| 主持人提问 | 当前问题、当前页、最近讲解、真实播放、表达偏好；指标和活动数据按问题内容选取 |
| 开场、告别、秒杀、抽奖、固定口播 | 使用编排中的固定台词或事件模板，不调用模型 |

普通问候不登记成持续需求。一次性问题在回应完整播完后退出待处理上下文；要求举例、调整讲解或选择展开方向的需求，直到对应讲解实际播完才完成。长期表达偏好单独保留。

每轮弹幕输入保留最新100条，由模型通读整批后决定点对点回答、合并共性问题或回应共同诉求；代码不预选前8条、不按话题聚类或排序。已答、过期、抽奖参与的消息保留在窗口中作为背景，以 `canReply=false` 标记，仍有效的未答消息才可回应。

弹幕回应返回 `answeredIds`，只在整段播放完成后消费这些 ID。消息使用本轮快照的短编号，实际平台 ID 由代码映射；最多覆盖100条，连续编号可写作 `c1-c100`，代码会展开并逐条校验，不能跨过不相关或不可回应的消息。合并回应中没回答的消息仍待处理；中断播放不消费。回复没有提供该字段时兼容 `selectedId` 或第一条可回应候选，不再用一个序号把整批弹幕都视为已答。

`onAir` 标明此刻真实播放，`recentTurns` / `aired` 是实际完成的讲解，`planned` / `plannedPredecessor` 是未完成的计划。弹幕或主持人之后的过渡只传一次，并只传仍需落实的要求，不把原回复中的问候一路带入后续预生成段落。已由前序计划承担的需求也不会再交给队列中下一段重复落实；计划取消后需求仍然有效。

实际公共规则与环节任务由 `server/director-prompts.mjs` 同时提供给模型和 `/api/prompts`；该接口还返回 `contextContracts`，列明代码约定的各环节输入。

输入总预算继续受120KB限制。窗口数量固定不超过100条；遇到异常长弹幕时，先缩短其他上下文，再均匀截短超长单条并标记 `contentTruncated`，保留全部消息编号，避免靠丢掉候选来满足预算。秒杀相关统一回应取真实活动状态；弹幕不会直接执行开启活动或调整时间。

## 各环节任务

### 开场欢迎（固定文案或事件模板）

```text
欢迎来到小云 Studio。我们一起看看，AI 虚拟主播怎样在云端工作。
```

### 内容讲解（模型任务）

```text
本轮是一段讲解，约30秒、最多135字（包含英文、数字和标点），只深入展开当前页的一个小要点。写不下的要点留给后续段落，不在本轮快速总览或收束整页。pageProgress由代码给出本轮段号、最低段数、已讲提纲和本轮focus。按focus推进新的事实、机制或具体场景；结合aired和planned避开已经展开的内容，不能为了凑段数反复概述产品定位、重复同一句事实，不能编造材料里没有的参数或承诺。
当前页通常需要多个讲解段，中途可以穿插弹幕和主动互动，它们不会消耗本页的讲解段数。pageProgress.canAdvanceAfterThisTurn=false时navigation必须stay；达到最低段数后，也只有当前页的重要内容已充分展开才选next，仍有新要点未讲就继续stay。不要第一段就总览整页然后要求翻页，也不要求每一段都总结或引导购买。
只有currentTransition存在时才简短承接；相关观众要求落实为具体解释、例子或讲法变化，对已落实的请求填写appliedRequestIds。没有新回应时直接推进当前页，不重复cue旧观众；先把当前页的内容讲清，再进入下一页。
```

### 弹幕回应（模型任务）

```text
你收到的是最近最多100条弹幕的完整窗口，不是预选的几个问题。先通读整批，由你判断本轮是点对点回应、合并共性问题，还是接住大家当前的共同诉求。约12秒、最多72字，不逐条回复整批。
只回应canReply=true的消息；其他消息带有已答、过期或抽奖参与等状态，仅供背景参考，避免重复。answeredIds使用本轮提供的短编号，列全本段确实回应覆盖的消息；同一段共同答复可以覆盖几十条乃至100条，不需要逐个点名。连续编号可简写为"c1-c100"，例如answeredIds:["c1-c85"]；只能包含实际覆盖且canReply=true的消息，不能跨过已答或不相关消息。只点对点回答时可以设置selectedId，统一回应时为null。不能引用本轮窗口外的编号。
点对点时，自然叫出真实可读昵称并简短概括原问题，再直接回答。共性问题多时，可以直接概括共同诉求，最多cue一两位代表，也可以不逐个点名；例如多位观众催秒杀，就统一接住“看到大家在催秒杀了”。区分同一人刷多条和多位观众，不把条数说成人数，不虚构大家都在问。问候自然回应，不把“你好”当成问题。昵称过长或全为数字、符号时称“这位朋友”，不念内部编号、连接名或长串账号。
秒杀相关答复结合本轮sale真实状态：active=true才能说本轮已开启并引导PPT右上角二维码；未开启时说明当前安排，不假称已开启。观众催秒杀只影响这段口播，不执行更改秒杀时间、开启活动或其他后台动作。
通常用两句，简短接住话题后直接给核心答案，句式自然变化；不逐字朗读长弹幕，不追加空泛承诺，不另起互动问题。后续讲解不再重复点名和这条已答问题，需要继续举例或调整讲解的要求由后续讲解落实。navigation=stay。
```

### 互动引导（模型任务）

```text
围绕 conversation.lastSource 刚讲的具体要点，或刚回应的观众问题，提出一个有助于继续讲解的简短问题或选择题。让观众的回答能够决定后续解释、示例或展开顺序；不要突然换话题，不用无关的点赞、分享话术替代内容互动。最多120字，navigation=stay。场景补充要求：承接刚讲的具体要点提出一个容易回答的问题，让观众的回答决定后续解释或示例；不要用泛泛的点赞、分享代替内容互动。
```

### 主持人提问（模型任务）

```text
结合当前讲解、最近对话和观众需求，直接回答主持人的问题。回答后用一句话接回原来的主题；主持人提出的相关解释要求与表达偏好应延续到后面的讲解。navigation=stay。
```

### 秒杀提醒（固定文案或事件模板）

```text
由已配置的商品入口、二维码展示时长生成固定提醒，不调用大模型。
```

### 抽奖（固定文案或事件模板）

```text
由真实奖品、参与口令、等待窗口和中奖结果生成固定说明、等待与开奖口播，不调用大模型。
```

### 收尾告别（固定文案或事件模板）

```text
感谢大家的陪伴，我们下次再见！
```

### 固定口播（固定文案或事件模板）

```text
逐字播放节目编排中保存的口播文案或录音，不调用大模型。
```

## 上下文如何接续

当前讲解 → 针对刚讲要点互动 → 接住观众回答或新要求 → 在下一段讲解中实际落实 → 继续推进内容。内部最多保留 10 段已播历史，模型按环节只取需要的部分；观众需求最多 12 条，20 分钟内跨页保留。只预生成而未播出的内容不算历史；一次性问答答完即完成；需要继续落实的讲解要求不会因一句承诺就完成。旧的未来段落在相关新请求到来时取消，当前正在播放的段落不受打断。

例如观众要求“别讲术语，用租房的例子解释”：弹幕段先承接，下一段实际使用租房类比解释云服务器；以后继续保持适合新手的表达，而不是只说一句“稍后会讲”后回到原稿。

## 同一页分段讲解与插播

`live.minPageTurns` 默认3，支持1–12，控制每页至少完整播出的讲解段数。`live.pageSeconds` 是每段目标时长，不是每页时长。未达到最低段数时，代码将模型过早的next改为stay；实际播完和预生成投影使用同一门槛，避免队列提前跨页。达到最低段数后仍由模型判断内容是否充分展开，不强制翻页。手动切页、结束和定时活动保持各自优先级。

讲解以不同重点逐段展开，已讲提纲和真实/计划历史共同避免重复。弹幕与主动互动不计入页内讲解段数；弹幕频率50时通常每两段检查一次，有真实问题可提前到一段；互动按独立段数与时间间隔触发。回应后先回讲解，节目顺序用于同时触发时的插入优先次序。插播会在当前语音播放期间预生成。

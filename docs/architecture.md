# 架构与状态

服务直接调用模型、TTS 与 ASR，不创建 DSH 会话。同一服务可保存多个直播场景，但一次只运行一个活动场景；所有控制浏览器操作同一场景，接收共享状态和各自的本机监听音频。

## 场景与运行实例

ProjectLibrary 管理场景清单、当前场景 ID 和各场配置目录。HTTP 服务共享管理员认证、上传素材库与状态订阅，并为当前场景创建独立的导播、模型调用、媒体和平台采集实例。未打开的场景只保留文件，不占用运行中的浏览器或推流进程。

切换前检查当前讲解、输出及未完成操作；正在运行时需操作者明确确认停止。切换会取消旧任务、关闭旧场的音频、编码器与采集浏览器，再建立目标场景的运行实例，保持未开播状态。切换期间拒绝新的场景操作，网页携带场景 ID，避免延迟请求写入另一场。目标初始化失败时会尝试清理新建资源并恢复原场实例，恢复后也保持停止；清理或恢复仍失败时返回错误，需要管理员处理。操作流程见[按直播场景保存](projects.md)，接口与冲突响应见[场景接口](api.md#直播场景)。


## 调度顺序

开场欢迎后进入内容讲解。每次完整口播完成，状态机重新选择下一步：已排队的活动、明确的主持人提问、新弹幕、适量互动、继续当前主题或翻页。抽奖拥有说明、参与窗口和结果三个子步骤。秒杀二维码的倒计时与讲解分开，因此无需停在某张活动页。

```mermaid
stateDiagram-v2
  [*] --> 准备
  准备 --> 开场: 开始 AI
  开场 --> 选择下一步: 整段播放完成
  选择下一步 --> 内容讲解: 继续当前主题
  内容讲解 --> 选择下一步: 整段播放完成
  选择下一步 --> 弹幕回应: 有新弹幕且达到频率
  弹幕回应 --> 选择下一步: 整段播放完成
  选择下一步 --> 互动引导: 满足回合数与冷却
  互动引导 --> 选择下一步: 整段播放完成
  选择下一步 --> 活动: 手动或定时排队
  活动 --> 选择下一步: 提醒或开奖完成
  选择下一步 --> 翻页: 模型判断主题已讲清
  翻页 --> 选择下一步: 下一页或循环首尾
  选择下一步 --> 收尾告别: 场控请求结束
  收尾告别 --> 已结束: 播放完成
```

网页显示当前阶段、原因、当前口播、后续准备、活动队列和转移历史。语音片段合成完成不代表播报完成：状态推进以音频混音器真实消费完该片段为准。下一段准备可与当前播放重叠；当场控暂停、打断、更换素材或结束时，旧的预生成结果会取消。

一页可有很多轮讲解。模型每轮返回 speech、navigation 和可选 interaction；只有 navigation=next 才正常推进。补充笔记可按页组织，旧页摘要会在换页时释放；身份和系统提示词始终在每轮请求中重建。模型输入有总字节上限，弹幕有时间和数量上限。没有长驻模型会话需要“释放”，只维护当前页的有界内存和请求取消信号。

## 媒体进程

每个活动场景的 MediaEngine 使用自己的 Chromium 用户目录。演示页和合成页分开，合成页读取演示页截图与安全节目状态。JPEG 帧经管道进入 FFmpeg；服务端把语音/BGM 解码并混合成连续 48kHz 双声道 PCM，再交给同一 H.264/AAC 编码器。

共享编码结果通过有界缓冲送给各平台独立的发送进程，以及独立的 MP4 录制进程；发送和录制使用已有编码包，不重复编码。单个平台可单独停止或重试，失败不会阻塞其他发送器和录制。输出引擎仍在运行与某一路已经有实际发送进度是不同状态，本地录像成功也不等于第三方平台收到直播。字段含义见[平台接口](api.md#平台连接)，配置方式见[多平台接入](platforms.md)。

本机监听从混音流复制音频，只有通过认证且已接通的控制浏览器才接收。首次点击口播、提问或开始讲解时，网页先等待音频握手和浏览器播放权限；显式本机静音偏好保存在该浏览器，不影响服务器的语音、推流或录制。关闭控制网页不会改变服务器输出时钟。

混音时钟按单调时间补齐 20 ms PCM 帧，短时调度延迟不会逐次累积；长时间挂起和编码背压限制追赶量，保留语音播放位置。BGM 音量与压低伴奏的切换平滑过渡，保存无关设置不会重启同一音乐文件的解码。网页监听将 PCM 合并成 80 ms 音频块，预留约 180 ms 缓冲并连续排期，以吸收页面和网络的短时抖动。

Chromium 意外退出时尝试恢复该实例及当前页；推流失败有有界重连。AI 两分钟没有实际语音能量且仍希望运行时会尝试恢复原流程，尊重暂停与主动停止。服务进程或主机完全退出后不自动向外开播，需要管理员确认。

渲染器同时检测浏览器断开、节目页或演示稿页关闭及崩溃。失效页面立即移出可用状态，等待旧进程有界退出后再启动替代浏览器，重新加载演示稿并恢复原页码。旧页面的延迟事件不能关闭新实例。初始化失败采用退避；连续三次失败后冷却 30 秒，随后由服务端自行重试，不依赖控制网页保持打开。画面重建保留最后一帧，不停止现有编码器、发送端和音频混音器。

每 30 秒检查当前容器的 cgroup 内存预算，扣除可回收文件缓存后达到 82% 时重建渲染浏览器以释放缓存，维护触发至少间隔一分钟。浏览器运行满两小时后的常规维护只在没有输出、没有待播语音时进行。复用初始空白标签页，避免常驻一个无用途的渲染进程；维护不会提高容器资源上限或操作其他服务。

## 数据归属

`STUDIO_DATA_DIR` 是整个服务的持久数据根目录，默认是 `.data`。管理员凭据与首次登录文件、场景清单 `projects.json`、上传素材索引 `assets.json` 和上传文件 `assets/` 在服务级共享。每场的配置、密钥、导播历史、语音文件、录像与浏览器资料保存在 `projects/<场景ID>/`。复制场景、首次升级和删除的具体范围见[场景数据说明](projects.md#首次升级与数据位置)。场景划分不提供不同管理员之间的访问隔离。

奖品结果和活动去重记录持久化；当前页讲解缓存、未读弹幕、报告采样和运行中的请求属于活动运行实例。报告导出来自有界采样，缺失指标保持缺失，带来源与采样时间。弹幕、指标与口播等事件写入场景私有日志；该兼容报告只用于当前运行诊断；历次直播数据使用 BroadcastSessions 的持久场次记录。多控制端访问同一状态，无任何控制端夺取“声音播报权”的操作。


## 实际直播场次

BroadcastSessions 在当前场景的 `broadcasts/` 目录下记录每次实际播出。配置仍由 ProjectLibrary 管理，原有场景 ID 和目录保持不变。输出的发送端/录像端有实际进度时才建立场次，重连期间保持同一 ID，全部输出停止后归档；手动外部开播由明确的开始/结束动作分界。

导播校验和去重后的弹幕、指标与口播事件写入该场次的 NDJSON 日志，元数据每 5 秒检查点并在结束时原子保存；历史事件不受实时弹幕队列 100 条的限制。进程意外退出后，从完整事件行恢复检查点后的统计，将旧场次标记为中断，以最后检查点或事件时间结束，不计服务器离线时间。日志末尾不完整的一行丢弃。列表和事件分别分页；JSON 导出流式读取，只包含导出开始时已记录的序列。每个平台分别记录指标，缺失保持 null/缺失，整体最高在线取单个平台的已知最大值。

复制场景只复制可复用配置及其引用素材，不复制场次日志；切换场景会结束旧场次。服务重启不自动恢复推流，也不推断已有旧日志属于哪次开播，因此旧版数据不会伪造为历史场次。

## 可配置节目与活动触发

`program` 保存 opening、closing、五种中间环节的 enabled 开关和完整 order。导播游标只在整段实际播完后前进；各环节按顺序获得机会，弹幕、互动与自动活动的条件未满足时跳过。手动口播和活动优先插入，抽奖说明至结果保持一个完整活动窗口。关闭环节会取消未完成活动，既有发奖记录保持不变。主动等待弹幕或定时时间使用 waiting 状态，不触发无声故障恢复。

`lottery.triggers` 显式选择 comment、popularity、interval、fixed，采用任一满足的组合语义。同一次检查同时满足的规则共用一轮抽奖并持久保存全部 claim，避免下一次检查再发起同一条件的抽奖。弹幕触发保留已接受消息的独立待处理引用，避免实时弹幕缓冲挤出触发词。人气指标仅使用对应字段 30 秒内的新鲜数据；在线人数与热度不互相替代。

# 视频号扫码与账号选择

## 推荐：同一个 Edge 工作区完成准备

本机运行 `npm run browser:local -- --server https://studio.example`，地址须与小云网页来源一致；默认使用已安装的 Edge，也可指定 `--browser chrome`。助手只监听本机 `127.0.0.1:18082`，为每个服务器、场景和连接创建独立浏览器资料，不读取日常 Edge 或 Chrome 资料。

视频号卡片依次显示「视频号登录」「同步到小云」「推流信息」。登录同步成功但尚未取得地址或推流码时，明确显示「登录已同步，还缺推流信息」，主按钮引导继续设置。只有登录验证和推流信息齐全后，主按钮才变为「开始推流」。推流中的标题、按钮和状态徽标统一使用最新输出状态，即使较旧的平台准备快照后到，也不会重新显示「开始推流」。弹幕连接单独展示采集状态、错误和真实弹幕数量，不把打开后台或推流成功当成采集成功。

点击「在 Edge 准备直播」或「在 Edge 继续设置」，助手打开同一个专用 Edge 窗口的两个标签页：当前场景的小云，以及视频号官方后台。小云登录通过管理员显式创建的 2 分钟一次性工作区凭证恢复，不要求在新浏览器重复输入密码。临时助手配对页会自动关闭。已经处于工作区时直接切换已有标签页，不反复配对或打开新窗口。

在视频号正常扫码、选择视频号或子用户，填写标题、上传封面，并由用户手动完成平台开播。显示推流信息后，点击页面右上角浮条的「同步回小云」。助手同步登录状态和当前明确标注的地址、推流码，自动回到小云的同一场景与连接。这里只保存信息；小云推流仍由用户点击「开始推流」。浮条可以收起，或随时点击「返回小云」。

同步包含专用视频号会话的 Cookie（含 HttpOnly）、localStorage、sessionStorage 和 User-Agent，不复制浏览器加密数据库或小云的管理 Cookie。服务器在新会话中验证登录，成功后接管；失败保留原会话。推流信息保存到对应连接的私有配置，密钥不进入状态快照。已在推流时不会覆盖不同的推流凭证。服务器会话文件权限 0600，支持服务器重启；同步成功后可以关闭本机窗口，服务器独立运行。

工作区使用已认证的小云标签页刷新单次、绑定场景和连接的同步授权，每次同步无需再次跳转授权页。独立工作区凭证与普通的 20 分钟配对授权不同：普通配对授权只允许导入视频号会话，不能创建小云管理登录。切换场景后，不对应的同步请求会被拒绝。

助手保留 `/connections/<连接编号>` 诊断入口并兼容旧链接。连接记录权限 0600，助手重启可接管自己创建的专用浏览器，退出助手不主动关闭这些窗口。后台标签页关闭时可重新打开；登录失效时从小云再次打开工作区。HTTPS 服务可直连；也可先建 SSH 转发，再指定 `--relay http://127.0.0.1:18083`，导入数据通过该隧道传输。

如果打开 `127.0.0.1:18082` 显示「拒绝连接 / ERR_CONNECTION_REFUSED」，说明当前电脑的助手未运行。先启动本机助手，再回小云点击「在 Edge 准备直播」取得新授权；旧链接中的工作区登录凭证仅有效 2 分钟。长期使用时，应把上述助手命令加入当前用户的登录启动项；macOS 可使用设置了 `RunAtLoad` 和 `KeepAlive` 的 LaunchAgent，退出后自动恢复。助手只需在准备和同步期间运行，服务器上的播出不依赖它。

专用浏览器使用独立进程启动，再通过本机 CDP 接管，避免浏览器库在助手进程退出时连带关闭窗口。助手启动时自动重新绑定仍然打开的工作区，不重新打开已经关闭的窗口。

`npm run test:workspace-login` 使用真实 Chromium 和离线官方站点模拟，验证两标签页、恢复小云登录、定位场景、三步状态、同步凭证、重复同步、助手重启和移动布局；不触发真实开播。`npm run test:session` 验证 HttpOnly Cookie、两种站点存储、一次性授权、账号隔离和失败保留旧登录。`npm run test:helper-ui` 验证旧诊断页和窗口恢复。`npm run test:browser-lifecycle` 在真实子进程退出和接管进程崩溃后检查窗口、HttpOnly Cookie、localStorage 和 sessionStorage 仍然保留。

## 服务器画面操作

在「外部连接 → 直播平台」添加或编辑视频号连接，直接点击「扫码登录视频号」。首次点击会先保存这条连接，再弹出服务器 Chromium 的真实登录画面，无需远程桌面。已有平台卡片也提供同样入口，复用这条连接的登录会话。

用微信扫描画面中的官方二维码。扫码后如果平台要求选择视频号、管理员身份或子用户，直接点击画面中的账号卡片和继续按钮。列表较长时可在图片上滚动，或使用向上、向下滚动按钮；「原尺寸查看」可以放大二维码和小字。二维码过期时点击画面中的刷新控件。支持微信官方内嵌二维码页；出现「加载失败，点击重试」时也可以直接点击画面中的重试区域。

账号选择流程会显示「请选择视频号或子用户」，不会被提前当成已经进入后台。进入后台后仍可通过明确的账号切换入口继续操作。关闭弹窗仅关闭本机窗口，服务器浏览器保持连接；每条连接分别保存浏览器资料，多个视频号互不共用登录会话。

登录成功、进入直播管理和收到真实弹幕分别显示。视频号扫码后可能返回首页；「打开直播管理」会在同一登录会话进入 `/platform/live/liveBuild` 直播控制页；管理首页 `/platform/live/home` 不会加入当前直播间或轮询弹幕，不能当成已完成弹幕连接。打开控制页不会点击开播、结束直播等控件，也不会打断尚未完成的账号选择。

## 设置直播并开播

视频号后台支持操作者直接点击控件、滚动、使用键盘，以及手动点击开播。中文标题可先点击画面中的输入框，再在下方文本框填写，点击「输入到选中位置」；可以勾选替换原文。画面获得焦点后也支持直接输入、粘贴、退格、Tab、Enter、Esc、方向键等。

上传封面时，先点击画面中的上传按钮，再点下方「上传封面 / 图片」，从本机选择不超过 10MB 的 PNG、JPEG、WebP 或 GIF。图片送到刚才触发的文件选择控件，可继续在画面中拖动裁剪和确认。临时文件仅在此连接的私有目录保存，断开时清理。

完成平台设置并由使用者手动开播，打开推流信息区域，点击「读取推流信息」。仅从当前画面的明确标签中读取服务器地址、推流码，显示供核对；「填入此连接的推流配置」会把地址和密钥保存到对应连接。密钥不会进入普通状态快照，关闭弹窗会清空临时展示。平台要求的手机授权、实名、开播权限或人工验证仍由使用者本人完成。

## 接口

管理员 `POST /api/platforms/:id/local-workspace` 接收 `{browser:"edge"}`，创建普通同步授权和独立的一次性工作区凭证。`POST /api/local-workspace/claim` 仅接受后者，在验证场景与连接后设置管理 Cookie。`POST /api/platforms/:id/preparation` 只接受本机非敏感心跳，不能伪造服务器验证时间或保存推流密钥。

管理员 `POST /api/platforms/:id/local-login` 创建一次性本机配对授权；配对接口 `POST /api/local-login/pair` 和导入接口 `POST /api/local-login/sync` 仅接受该授权的 Bearer token，不授予状态读取、配置修改、开播等管理权限。导入的数据只限视频号站点，不接受其他网站的 Cookie 或存储。

创建平台连接的 `POST /api/platforms` 响应返回本次创建的 `connection.id`，前端据此直接打开该连接的登录页。凭证仍仅保存在服务器。`platform.chat.login` 打开独立浏览器，截图通过 `/api/platforms/:id/frame.jpg` 获取。

`platform.chat.click` 使用 `{id,x,y}`，坐标为原始截图像素。`platform.chat.scroll` 使用 `{id,x,y,deltaY}`，deltaY 范围为 -600 到 600。`platform.chat.type` 使用 `{id,text,replace}`，最多 10000 字，只输入当前聚焦的可编辑控件。`platform.chat.drag` 使用 `{id,fromX,fromY,toX,toY}`，用于裁剪、滑块等手动拖动。`platform.chat.key` 使用 `{id,key}`，支持公开按键集合。所有视频号操作限定官方后台及官方微信登录内嵌页，按连接串行执行。

`POST /api/platforms/:id/browser/upload` 接收最大 10MB 的原始图片，校验图片签名，发送给已触发的文件选择控件。`POST /api/platforms/:id/browser/stream-info` 返回当前明确标注的 `{rtmpUrl,streamKey}`，不写入配置。操作要求管理员认证和当前 `X-Studio-Project`，接入弹幕密钥和内部渲染令牌均无操作权限。状态包含 `accountSelectionRequired`、`livePageReady`、`fileUploadRequested`。

## 验证

`npm run test:login-ui` 使用真实的控制浏览器和采集浏览器，配合本地模拟页面验证扫码和子用户选择、保持登录进入直播管理、中文标题、按键、封面上传、由操作者显式点击开播、读取并私密保存推流信息，以及多连接隔离和关闭弹窗保留连接。测试不登录真实账号、不触发真实开播。官方二维码可达性另在 Linux 镜像中以全新会话检查。

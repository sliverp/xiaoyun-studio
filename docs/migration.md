# 从旧项目导入

本仓库是独立服务，不是原有安装的覆盖升级。迁移命令只读取旧项目文件，将允许的演示稿和已校验录音复制到本仓库的数据目录；不会改动旧服务、账号、浏览器窗口、OBS、配置文件或已有运行流程。

```sh
npm run migrate -- --source /path/to/previous-project
```

执行前停止新 Studio 的服务进程；只暂停 AI 不够。导入命令直接写持久文件，运行中的服务不会自动重读设置与素材索引。导入完成后重新启动 Studio，再核对素材和口播。旧项目服务不需要停止。

默认复制旧项目 `materials/live-1024-deck/site` 中的演示资源、合并笔记、口播文案和 stage-audio 清单中通过 SHA-256 校验的音频。这是针对上述目录的导入器，其他格式的旧项目应通过素材上传与场次配置接入。导入结果可在新导播台素材库选择；默认不切换当前素材。给命令增加 `--apply` 才更新 Studio 当前场次的演示地址、笔记、系统话术，并追加导入的固定口播，不会自动新建场次或修改其他场次。

原项目中的密钥、浏览器配置、平台登录、观众信息、历史录像和开播状态都不导入。配置新服务所需账号时重新填写，避免两个系统误共享运行状态。新系统只会在管理员点击开始后运行。

导入命令默认数据目录是仓库 `.data`，用 `--data /new/data/path` 指定实际服务的数据根目录；该脚本不读取 `STUDIO_DATA_DIR`，应显式传入。程序拒绝写入旧项目内部。导入的文件留在私有数据目录，默认 `.data` 已被 Git 忽略；自定义目录也应放在仓库之外或自行加入忽略规则。

```sh
npm run migrate -- --source /path/to/previous-project --data /path/to/studio-data --apply
```

Studio 从单份配置升级到多场次时，会自动复制原资料到「原配置」；这是 [场次首次升级](projects.md) 的行为，不需要运行旧项目素材导入器。完整实例的转移则应按 [备份与恢复](deployment.md#备份升级与恢复) 处理，避免漏掉共享素材、场次清单和私有凭证。

公开演示素材只包含仓库内注明来源的人物、BGM 和示例口播。部署者可通过上传与配置替换。PPTX 不直接解析；请转换为 HTML 或 PDF。
